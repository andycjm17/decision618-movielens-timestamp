# 中文讲解与备讲说明

英文 slides 共 7 页，计划时间合计 5 分钟。以下是理解和备讲说明，不是要全部在台上念出的中文译稿。


## 第 1 页：The next movie recommendation（0:00-0:25）

项目是为一个假设的订阅制电影平台生成十部候选电影。商业目标是帮助用户更快找到愿意开始观看的影片。我们现在测量的是离线推荐相关性，尚未证明收入、观看时长或留存提升。


## 第 2 页：MovieLens and rating activity（0:25-1:05）

团队 GitHub 当前只有数据清洗 notebook。它已检查缺失值、重复评分、分值范围，转换时间、拆分类型、提取年份、解码用户类别，并合并成 1,000,209 行、11 列。保存 Parquet 的输出存在 notebook 中，但四个 Parquet 文件没有上传仓库。本地模型实验是后续扩展，应与仓库清洗进展区分。


## 第 3 页：Course method and project extension（1:05-1:50）

老师用 softImpute 做矩阵分解，预测用户会给电影几颗星。我们的 adapted NextItNet 根据最近电影 ID 预测下一次评分对应的电影。它与老师的方法共享“从用户互动学习偏好”的思路，但增加了近期历史和非线性编码，也更改了预测目标。评分低的电影在当前实验中仍算一次互动。


## 第 4 页：Evaluation setup（1:50-2:30）

每位用户最后一条评分是测试，倒数第二条是验证。训练评分有 988,129 条，每个人第一条没有过去记录，因此训练的下一物品目标数为 988,129 - 6,040 = 982,089。它们来自 6,040 条用户序列，并非 982,089 位独立用户。代码采用不重叠分块，每个块内部做逐位置预测，跨块不保留完整历史。


## 第 5 页：NextItNet leads the tested ranking baselines（2:30-3:30）

19.94% 的 HR@10 意味着：在 6,038 名可评估用户中，约五分之一的真实最后评分电影出现在模型推荐的前十名。不是 19.94% 的评分预测正确，也不是点击率。与 item-kNN 的 7.40% 相比提升 12.54 个百分点。评分型 SVD 的目标不同，所以不要用它的低 HR 声称所有矩阵分解都不如 NextItNet。


## 第 6 页：A stricter timestamp check（3:30-4:15）

53.21% 的相邻评分时间完全相同，不能据此识别先看哪部电影。严格时间子样本只要求最后评分晚于前一条，共 3,494 名可评估用户，仍不是完整无并列序列。固定权重打乱输入只能说明预测敏感，不能证明顺序的因果价值。


## 第 7 页：A limited pilot is the next step（4:15-5:00）

后续最有价值的是全球按时间切分、用相同训练目标比较矩阵分解和 NextItNet，再评估是否值得部署。老师的 hybrid 思路可以做类型偏好加权、冷启动候选和多样性重排；目前这些只是改进方案。新用户已有热门推荐 fallback，新电影的 metadata route 尚未实现。


## 老师的方法与我们的改进方向

| 项目 | 老师的示例 | 当前项目 | 下一步改进 |
|---|---|---|---|
| 预测目标 | 缺失的 1-5 星评分 | 下一次评分电影 ID | 保持目标一致，再比较模型 |
| 模型 | softImpute 矩阵分解 | adapted NextItNet、item-kNN、Popularity、评分型 SVD | 增加以排名为训练目标的矩阵分解 |
| 划分 | 随机 99/1，训练内交叉验证 | 用户内最后一条测试、倒数第二条验证 | 全球按时间划分，减轻跨用户时间泄露 |
| 指标 | RMSE、MAE、样本外 R² | HR@10、NDCG@10、MRR、目录覆盖 | 加入历史长短分组和业务 A/B 测试 |
| 元数据 | 课件讲 CF 预测与类型等变量做 ensemble | 类型用于展示；当前主模型只用电影 ID | 类型偏好、冷启动候选、多样性重排 |


老师课件 PDF 第 59 页记录 CF RMSE 0.916，ensemble 0.900，约下降 1.75%。这是老师示例结果。老师 notebook 保存结果为 RMSE 0.919，属于另一份运行记录，不能混为本项目结果。也不能把这些 RMSE 与我们的 NDCG 数值比较大小。


当前 GitHub 清洗 notebook 还可补：合并键唯一性和外键匹配验证；明确 UTC 时间；导出数据与依赖说明；训练内拟合电影 ID 映射及特征；类型需要多标签编码，年龄与职业是类别而非连续数值。用户没有评分的电影不能直接算负反馈。

## 教师可能追问

**为什么没有直接照搬老师的算法？** 保留课程的协同过滤思路，将产品决策定义为推荐下一部可能发生互动的电影。评分预测和下一物品排名各自有用，但评估必须与目标对应。

**NextItNet 是不是已经证明更先进？** 它在当前设置下优于已测试排名基线。没有证明普遍优越，也没有证明顺序本身是全部提升的原因。

**为什么是最近十部？** 在 10、20、50 三个窗口的验证集中，10 的 NDCG@10 最高。它是有限搜索中的选择，不代表所有数据的最优窗口。

**这个项目能算 ROI 吗？** 不能从 MovieLens 实算。需要曝光、开始观看、留存、贡献毛利和系统成本，先用随机实验测量。

**分工是否已确认？** 附录按要求先写了建议分工。三位成员须确认实际工作后修改，不应直接当作真实历史分工提交。
