The Netflix Prize
Collaborative Filtering and Clustering
• In October 2006, Netflix ran a contest inviting anyone to 
develop a recommendation method that could beat Netflix’s 
own algorithm called Cinematch 
• This competition took three years
• The winning team won Cinematch by over 10%
• Cinematch predicts user ratings of  unseen movies (rating 1-5).
• $1,000,000 prize to the team that could best beat Cinematch.
• Catalyzed research innovation in recommender systems
• Fostered collaboration between academic researchers and industry 
practitioners
• Crowdsourcing innovation with over 44,000 submissions in 180 
countries

Limitations 
Collaborative Filtering and Clustering
• Rely heavily on manually curated user features and movie 
characteristics. 
• Users have varied preferences that cannot be “written down”. 
• Movies have features that also are not easily characterized. 
• Missing Piece: Leveraging similar users (collaboration)
• Users who have similar rating history are likely to be similar in 
preferences. 
• Our algorithm should learn from similar users, without explicitly 
knowing “why” users are similar.

Collaborative Filtering Approaches
Collaborative Filtering and Clustering 22
• Core Principle: Similar users should like similar movies.
• Leverages collective behavior of  the entire community of  users.
• Approach 1: Neighborhood-Based 
• Use past ratings to define “similar” users. Predict a weighted average 
based on these similar users.  
• Approach 2: Model-Based 
• Define user archetypes to capture “types” of  (similar) users.
• Model each user’ as a weighted combination of  user archetypes 
• This lecture will focus on the model-based approach, which is 
more widely used in practice. But let’s see how the 
neighborhood-based approach works. It is quite simple.

Core Concept: Archetype
Collaborative Filtering and Clustering 25
• Concept: Archetype, a typical profile or behavior pattern.
• Archetype 1: enjoys action, adventure, physical drama
• Archetype 2: enjoys exploration of  relationships, interpersonal drama
• Archetype 3: emotional drama – suspense, fear, mystery, intrigue
• …
• Archetype 9: enjoys chronicles of  facts, events, presentation
• Assumption: Each person’s movie taste is some weighted 
combination of  the preferences of  the archetypal user.
• Archetypes are like “clusters”, except that each user is a 
mixture of  many archetypes instead of  being assigned to one 
archetype.

• 4 users and 5 movies, with 14 observed ratings and 6 missing ratings.

• The kid at heart user likes movies that are animated or feature children
• The artist user likes movies which are artsy and less mainstream (not Hollywood 
blockbusters)
• Each user is a composition of  these two archetypes.

• - 1 = fits the opposite of  this archetype 
• Predictions can be made for the missing entries based on the user 
compositions and archetype ratings. (Details to come…)
• The archetype ratings and user composition are both discovered through the 
model training process. (Details to come…)

Model-Based Collaborative Filtering 
Collaborative Filtering and Clustering 45
• The model we just described is an example of  “model-based collaborative 
filtering”, also referred to as matrix factorization.
• Model user preferences as a linear combination of  archetype preferences. 
• Calculate the “best” archetypes and weights to explain the observed data.
• This approach shares similarities with clustering in the sense that it produces 
archetypes that we hope to be able to “interpret” intuitively.
• Very active area of  model research and development—and good R packages
• softImpute, from Prof. Rahul Mazumder (MIT Sloan) and Prof. Trevor 
Hastie (Stanford Stats)
• R package much better than Python package…

• If  we have too few archetypal users, the predictions will be too 
rough—we will not capture important patterns in the data
• If  we have too many archetypal users, the model will overfit to the 
training set—resulting in poor out-of-sample performance
→ We will use cross-validation to select the value of  𝑘 that yields 
the best prediction on unseen data
• For each value of  𝑘, perform 20-fold cross-validation*
• Record the average R2 using the current value of  𝑘.  Call it AvgR2
• Choose the value of  𝑘 that yields the highest value of  AvgR2
*Please don’t confuse the k from k-fold cross-validation with the number of  archetypes k

Unsupervised Learning
Collaborative Filtering and Clustering 77
• Previously, we have seen datasets with a dependent variable that we are 
trying to predict as a function of  some independent variables
• These are called supervised learning problems
• In clustering, there is no dependent variable to predict; instead, we 
aim to create groups of  “similar” samples/observations
• These are called unsupervised learning problems
• No training/testing split for unsupervised learning
• Without a dependent variable, out-of-sample performance is irrelevant
• Unsupervised learning is used for summary / exploratory analysis
• Unsupervised models are more subjective to interpret
• Unsupervised models are also more difficult to validate

Problems with k-means/AHC
Collaborative Filtering and Clustering 149
• k-means/AHC do best when the clusters exhibit:
1. Circular/spherical shaped (uncorrelated variables); and
2. Similar variances (“dispersion patterns”) across clusters
• Unfortunately, oftentimes clusters are:
1. Best described by elliptical shapes (correlated variables); and/or
2. Have different types of  variances (different types of  ellipses)
    In these situations, k-means/AHC will often not perform well

• Gaussian Mixture Models (GMMs) provide an improved method for 
clustering when clusters are elliptical and/or may have different variances 
among the clusters
• Clustering is based upon the multivariate analogue of  the Normal 
(Gaussian) distribution
• Here the “bell” of  the bell-shaped curve is shaped like a real bell


PDF PAGE 148
Gaussian Mixture Models
Collaborative Filtering and Clustering 151
• We imagine that there are k distinct “multivariate” Normal distributions 
which give rise to the data (with unknown means, standard deviations, and 
“correlation” structures)
• But we do not know which individuals came from which distribution 
• Nonetheless, we can compute estimates of  the values for the means, 
standard deviations, and correlation structures that would fit the data best, 
using what is known as the Expectation-Maximization (EM) algorithm
• Once we have these estimates, we can actually calculate the probability 
that an individual observation is from a given cluster
• We then assign each individual to the cluster with the highest probability

Clustering and Customer Segmentation
Collaborative Filtering and Clustering 156
• Clustering for customer segmentation is now pervasive
• Better understanding of  key customer types and their prevalence
• Design of  appropriate engagement strategies, tailored to each segment
• Key steps in clustering analytics:
• Aim for data to be compatible in scale through standardization
• Identify relevant clusters with k-means, or hierarchical clustering, GMMs, or 
PAM
• Analyze cluster centroids (or medoids) to interpret the type of  customers in 
each cluster and determine appropriate implications for management
• Clustering cannot be validated with out-of-sample predictions
→ very important to engage decision-makers throughout model building

Comparison of  Clustering Methods
Collaborative Filtering and Clustering 157
• k-means, hierarchical clustering, and GMMs often yield consistent insights
• Still, the methods have different strengths/weaknesses
• k-means clustering
• Is more computationally efficient — hence scalable to ever-larger datasets
• Hierarchical clustering
• Flexibility through various distance and cluster dissimilarity metrics
• Amenable to iterative decision making — at various levels of  granularity
• GMMs
• Best when clusters are thought to be “elliptical” with potentially different 
correlations and variances
• Many modeling issues can have significant impacts on results
• whether to standardize data, how to quantify “distance”, how many clusters to use, 
etc.
