Review: What is a CART Model?
Data Analytics for Business — CART 1
• CART is a “tree”-based model used to make predictions.
• Given the observed values of  the independent variables, just “follow the splits” 
to the final node
• At the split, go left if  “yes” and go right if “no”
• Follow the splits to the end/bottom of  the tree and read off  the value.  That’s it!

Cross-Validation to choose ccp_alpha
Data Analytics for Business — CART 22
• It is common to perform 5-fold or 10-fold cross-validation
(we will perform 10-fold cross-validation here)
• One parameter is varied (ccp_alpha). min_samples_leaf is 
fixed throughout.
• We use our losses of  𝐿𝐹𝑁 = 20  and  𝐿𝐹𝑃 = 1  
• For ccp_alpha = 0, 0.01, 0.02, 0.03, …, 1 :
• We will do cross-validation with the value of ccp_alpha.
• We will record the average loss value over all folds.  Call it AvgLoss.
• Finally, we will choose that value of  ccp_alpha that achieves the 
lowest value of  AvgLoss.
• Then fit a (final) tree on the full training data with this value of  
ccp_alpha.

Why Does This Promote Diversity?
Random Forest and Boosting 73
• Recall that CART typically chooses the split that reduces impurity (SSE 
or Total Loss) the most. 
• Randomly selecting the candidate predictors at each split results in 
more diverse trees with lower correlation.
• Consider an extreme example where there is one strong feature variable (say 
GPA) and other very weak variables (say citizenship)
• In this case, CART would almost always pick the strong variable for its first 
split. As a result, all trees will be quite similar, and the trees’ predictions will 
be highly correlated (hence less diverse)
• Trade-Off. However, sampling too few predictors at each split might 
result in poorly optimized splits and might worsen predictive ability.

build one tree on each server, or 2 trees on 250 servers, or …
• The time it takes to build a random forest using parallel architectures 
is proportional to the time it takes to build a single CART tree

Random Forest and Boosting 98
• Random forests are built by sampling data from the training set

PDF PAGE 97
Out-of-bag Predictions: Principles
Random Forest and Boosting 99
• Each training set observation (row) appears in roughly 63% of  the 
bootstrap (bag) samples*
• Out-of-bag prediction: for each row , we use all the trees that did 
not use that row in the fitting process ( ~37% of  the trees)
• Regression: predict the average over all of  these trees
• Classification: predict the most common class among all of these trees
→ Estimates the out-of-sample performance (R 2, RMSE, MAE, etc.) 
using only the training data
→ An efficient way to estimate how well random forests generalize to 
“new” data, without having to do k-fold cross-validation

Gradient Descent Algorithm
Random Forest and Boosting 108
• Algorithm:
1. Current point is  x  
2. Compute f’(x)

•  is called the “step-size” among mathematicians, but in Machine

• A smaller learning rate will take us longer to get near to the 
solution, but is likely to result in a higher accuracy solution

Random Forest and Boosting 130
• Start with an initial tree 𝑔1 and calculate its residual 𝑟1. 
• For each iteration 𝑖 = 2, 3, … , 𝐵
• Fit a CART model 𝑓𝑖 to the residuals 𝑟𝑖−1
• Calculate 𝑔𝑖 = 𝑔𝑖−1 + 𝜂 ⋅ 𝑓𝑖−1 
• Calculate new residuals 𝑟𝑖 as 𝑦 − 𝑔𝑖
• 𝑔𝑖 is the prediction using the CART models 1, 2, … , 𝑖 out of  B.
• The residuals 𝑟𝑖 are the “errors” between the actual value (y) and the 
prediction 𝑔𝑖. Each CART model 𝑓𝑖 tries adjust the prediction 𝑔𝑖−1based on 
the residuals 𝑟𝑖−1.
• We often set 𝑔1 (the initial model) to be a tree with 1 leaf that predicts 
classical baseline model  ത𝑦𝑡𝑟𝑎𝑖𝑛 (the average of  the observations in the 
training set). But this is not required.

Building Boosted Trees
• Each trees 𝑓1, 𝑓2, … , 𝑓𝐵 are intentionally limited to be shallow/weak 
trees (very few splits, not very deep trees). 
• These types of  trees are sometimes called “tree stumps” or just 
“stumps”
• Each tree is limited in its ability to fix residuals, but each tree

• Many small changes lead to more stable models than a lot of big 
changes.

Tuning Parameters for Boosting
The class GradientBoostingRegressor  in sklearn implements boosting for 
trees, and has four main hyper-parameters:
• n_estimators: Total number of  boosting iterations B.
• max_depth: total number of  splits performed in each tree
•  Setting to 1 allows only for a single predictor variable; setting to 2 allows for  
pairwise interactions
• Such small trees are sometimes called “tree stumps” or just “stumps”
• learning_rate: ( 𝜂 ) controls the extent to which each new tree contributes to 
the additive model:
 𝑔𝑗+1 𝑥1, … , 𝑥𝑘  = 𝑔𝑗 𝑥1, … , 𝑥𝑘  + 𝜂 𝑓𝑗+1 𝑥1, … , 𝑥𝑘  
• min_samples_leaf: minimum number of  samples in a leaf  (same as in 
CART).

Stochasticversion of Boosting
• In Random Forests, we have seen the power of  introducing randomness into our 
fitting algorithm through the use of  bootstrapped samples (bagging)
• For Boosting, a slight variant of  Boosted Trees which induces randomness also 
provides improvements in performance
• In each iteration, instead of  using the entire training set to fit the next tree, we 
choose a random subset of  the training set, where each observation is chosen to be 
in the random subset with probability  p.
• The rest of  the Boosting method is exactly as described earlier
• It is typical to use  p = 0.5.  This is controlled by the subsample parameter in 
GradientBoostingRegressor , and the default is  p = 1.0.  It is sometimes set 
smaller when n is very large.

In Random Forests:
• Deep trees are trained independently in 
different bootstrap samples and 
combined by average/majority vote.
• Each tree is designed to be diverse using 
randomness.
In Boosted Trees:

combined sequentially.
• Each new tree is designed to tackle the 
residuals (errors) from the previous 
additive tree model

The Punchline
Random Forest and Boosting 153
• Random Forest 
• Each tree has great in-sample fit, but overfits significantly. 
• Solution: Averaging many trees keeps the in-sample performance, but 
reduces the overfitting. 
• Boosted Trees 
• Each tree is simple (little overfitting) but cannot fit the in-sample data 
well.
• Solution: Creating trees sequentially keeps the low overfitting tendency, 
but gradually improves the in-sample fit.
Out-of-Sample Error = In-Sample Error + Tendency to Overfit
For those interested, look up the bias-variance tradeoff  in statistics.
